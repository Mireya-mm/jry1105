7. 知识库（RAG）设计

首批入库文档类型：

  • 运输节点规则：入库为可检索知识条目，含来源、版本、生效时间
  • 异常判定标准：入库为可检索知识条目，含来源、版本、生效时间
  • 计费规则：入库为可检索知识条目，含来源、版本、生效时间
  • 签收凭证规范：入库为可检索知识条目，含来源、版本、生效时间

实现要点：

  1. 将 kb/docs/ 下文档按段落切分（200–400 字），记录 doc_id / 来源 / 版本 / 生效时间。
  2. 用 TfidfVectorizer 建索引；检索返回 top-3 片段 + 相似度 + 来源。
  3. 提供 POST /api/kb/search；Harness 的「检索」步骤复用该能力。
  4. 回答必须带来源引用，无法命中时返回「知识库未覆盖」，禁止编造。

8. Harness 智能体编排工程

流程主线：运单接入 → 节点跟踪 → 异常识别 → 核验处理 → 签收/对账。

智能体清单：

  • 节点跟踪 Agent：结构化输入→LLM推理→结构化输出，纳入 Harness 状态机
  • 异常识别 Agent：结构化输入→LLM推理→结构化输出，纳入 Harness 状态机
  • 核验 Agent：结构化输入→LLM推理→结构化输出，纳入 Harness 状态机
  • 对账 Agent：结构化输入→LLM推理→结构化输出，纳入 Harness 状态机

状态机（Python enum + 循环）：

class Stage(str, Enum):
    UNDERSTAND = "understand"   # 解析输入 -> 结构化意图
    RETRIEVE    = "retrieve"    # 调知识库检索证据
    REASON      = "reason"      # LLM/Mock 推理，产出建议
    ACT         = "act"         # 写入业务对象 / 生成交接
    SELFCHECK   = "selfcheck"   # 校验必填字段与证据引用

要求：

  • 有界重试：自检失败最多重试 2 次，仍失败则标记 needs_human=true。
  • 全链路 trace；/api/harness/run 返回 {result, trace, trace_id}。
  • LLM 接口做成 call_llm(prompt)->str，默认 Mock（规则模板），便于离线运行。
